# Integration Test Design

## 目的

システムの設計書や関連ファイルを読み取り、要件との対応が追跡できる総合テスト設計を作成します。入力資料には JSON などの構造化データのほか、表計算・文書ファイルが含まれる場合があります。

## 作業時の指針

- 作業開始時に `input/` とその配下の資料を確認し、形式・対象システム・対象範囲を把握してください。
- 資料に記載された事実と、分析上の推測・未確定事項を区別してください。不明点を事実として補完せず、確認事項として明示してください。
- 要件、機能、テスト観点、テストケースの対応関係を維持し、根拠となる資料や識別子を記録してください。
- 正常系、異常系、境界値、状態遷移、データ組合せ、外部連携など、仕様に応じた観点を検討してください。
- 既存の入力資料を変更せず、中間成果物は `intermediate/`、最終成果物は `output/` に配置してください。
- 構造化データを作成する場合は、形式の妥当性と必須項目を確認してください。

## ディレクトリの役割

- `.github/skills/`: 仕様分析、文書分析、テスト設計、成果物生成、レビューの手順や補助資料
- `input/`: 設計書、テンプレート、ガイドラインなどの入力資料
- `intermediate/`: 分析結果やテスト観点などの中間成果物
- `output/`: レビュー可能な総合テスト設計の最終成果物
- `scripts/`: 必要に応じた共通処理や検証用スクリプト

## 成果物の品質

- 各テストケースは、前提条件、入力・操作、期待結果が判別できるようにしてください。
- 重複や曖昧な表現を避け、実施・判定可能な粒度で記述してください。
- 資料から導けない期待結果や仕様は作り込まず、未確定事項として扱ってください。
